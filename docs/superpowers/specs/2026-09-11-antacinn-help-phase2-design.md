### 2.3 ข้อมูลทางการที่ค้นพบ

ชุดข้อมูล **"อุบัติเหตุบนโครงข่ายถนนของกระทรวงคมนาคม"** (datagov.mot.go.th ชุด `roadaccident`, สัญญาอนุญาต Open Data Common) ซึ่งเอกสารโครงงานอ้างไว้แล้วในบทที่ 6.3 มี **ข้อมูลรายเหตุการณ์พร้อมพิกัด** ดึงผ่าน API ได้จริง

- จังหวัดสงขลา ปี 2563–2568: **1,466 เหตุการณ์ ทุกเหตุการณ์มีพิกัด เสียชีวิตรวม 206 ราย**
- มีฟิลด์ ผู้เสียชีวิต / บาดเจ็บสาหัส / บาดเจ็บเล็กน้อย ตรงกับน้ำหนัก 5/3/1 ของทีมพอดี
- มีวันเวลาเกิดเหตุ (หา peakMonths/peakHours จากข้อมูลจริงได้) และมูลเหตุสันนิษฐาน (เขียนคำแนะนำจากหลักฐานได้)
- ครอบคลุม **เฉพาะถนนในความดูแลของกระทรวงคมนาคม** (ทางหลวง ทางหลวงชนบท) ไม่รวมถนนเทศบาลในเมือง

ข้อควรรู้เกี่ยวกับชุดข้อมูลนี้

- รูปแบบวันที่ต่างกันถึง 4 แบบในแต่ละปี (ISO, `M/D/YYYY`, เลขลำดับวันของ Excel, และแบบผสม) ต้องมีตัวแปลงที่มีเทสต์คุม
- ปี 2565 มีแค่ 40 เหตุการณ์ (ปีอื่นราว 235–328) น่าจะเป็นข้อมูลต้นทางไม่ครบ ไม่ใช่อุบัติเหตุลดลงจริง
- ชุด `data.go.th/dataset/100-risk-map` ที่เอกสารอ้างถึง เป็นข้อมูลของ **กรุงเทพมหานคร** ใช้กับสงขลาไม่ได้ (เอกสารอ้างไว้ในฐานะต้นแบบโครงสร้างข้อมูล ซึ่งยังถูกต้อง)

จุดรวมเหตุที่พบในเขตหาดใหญ่ (ตัวอย่าง ต้องยืนยันอำเภอก่อนใช้): ทล.43 กม. 2.6–3.3 เกิดเหตุ 19 ครั้งบนทางโค้งเดียวกัน สาเหตุหลักขับเร็วเกินกำหนด, ทล.414 (ถนนลพบุรีราเมศวร์) กม. 12 และกม. 22, ทล.407 (ถนนกาญจนวนิช) กม. 17–19

### 2.4 ข้อมูลสภาพอากาศจริง

Open-Meteo ให้ข้อมูล **ความสูงคลื่นปัจจุบัน** และ **ฝน** ที่พิกัดใดก็ได้ ฟรี ไม่ต้องใช้คีย์ ทดสอบแล้วใช้ได้กับหาดสมิหลา (คลื่น 0.12 ม. เมื่อ 2026-09-11) และน้ำตกโตนงาช้าง ตรงกับที่เอกสารบทที่ 8 เขียนไว้ว่าอยากทำในอนาคต

## 3. ขอบเขตงาน — แบ่งเป็น 5 ช่วง แต่ละช่วงส่งมอบได้เอง

### ช่วง A — แก้ของที่พังและไม่ปลอดภัย (ต้องทำก่อนทุกอย่าง)

- **A1** แก้จอขาวหลังออกจากโหมดเดินทาง (F1)
- **A2** แก้พิกัดทั้ง 12 จุดและเส้นทางสำเร็จรูป 3 เส้นให้ตรงกับ OpenStreetMap (F2) และบันทึกที่มาของพิกัด
- **A3** เพิ่มเทสต์ตรวจความถูกต้องของไฟล์ข้อมูล (id ไม่ซ้ำ, คำนำหน้าตรงอำเภอ, พิกัดอยู่ในพื้นที่, `source` ไม่ว่าง, จุดที่ `verified: true` ต้องมีแหล่งทางการ) — คุ้มครองทีมตอนกรอกข้อมูลด้วยมือ
- **A4** ค้นหาแบบเรียงความเกี่ยวข้อง (F3)
- **A5** แก้แถบฤดูกาลให้พูดตรงกับข้อมูล (F4) และหัวข้อชนกันบนจอมือถือ (F6)
- **A6** ตรวจและแก้ F7 (จุดที่บันทึกใหม่ต้องโผล่ทุกหน้าจอทันที)

### ช่วง B — ฟีเจอร์เด่นสำหรับการสาธิต

- **B1 เตือนด้วยเสียงและการสั่น** (S1) พูดภาษาไทย เช่น *"ระวัง อีกประมาณ 500 เมตร หาดชลาทัศน์ ระดับเสี่ยง ถ้าเห็นธงแดงห้ามลงน้ำเด็ดขาด"* พร้อมปุ่มปิดเสียง ระยะในป้ายเตือนนับถอยหลังสด (F5)
- **B2 จำลองการเดินทาง** — ปุ่ม "▶ จำลองการเดินทาง" ให้คนขับเสมือนวิ่งตามเส้นทางจริง เสียงเตือนดังจริงเมื่อผ่านจุดเสี่ยง **ไม่ต้องออกไปขับรถจริง** แก้ปัญหาที่เอกสารบทที่ 7.3 เขียนไว้ว่าต้องเตรียมวิดีโอสำรองสำหรับนำเสนอ และทำให้ทดสอบโหมดเดินทางในเบราว์เซอร์ได้ด้วย
  - สมมติความเร็วรถ 60 กม./ชม. แล้วเร่งเวลาได้ 3 ระดับ: **×1** (เวลาจริง), **×10**, **×30** ค่าเริ่มต้น ×10 เพราะเส้นทางหาดใหญ่–สงขลา 28 กม. ที่เวลาจริงใช้ 28 นาที นานเกินไปสำหรับการนำเสนอ ที่ ×10 เหลือราว 3 นาที
  - มีปุ่มหยุดชั่วคราว เล่นต่อ และเริ่มใหม่ แสดงแถบความคืบหน้า
- **B3 รู้ตำแหน่งบนเส้นทาง** (S3) ถ้าเริ่มจากหน้าวางแผนเส้นทาง แสดง *"จุดเสี่ยงถัดไป: สะพานติณสูลานนท์ · อีก 4.2 กม. ตามเส้นทาง"* ถ้าออกนอกเส้นทางเกิน 300 ม. กลับไปใช้ระยะเส้นตรงพร้อมบอกผู้ใช้

### ช่วง C — ทำฟีเจอร์ตามเอกสารให้ครบ

- **C1 เลือกต้นทางปลายทางเอง** (S2) ต้นทางเป็น "📍 ตำแหน่งของฉัน" หรือสถานที่ใดก็ได้ ปลายทางเป็นสถานที่ใดก็ได้ เลือกจากรายการที่ค้นหาได้ เส้นทางสำเร็จรูปเดิมยังอยู่เป็นทางลัด
- **C2 สถานที่ยอดนิยม** (S5) ไฟล์ใหม่ `data/places.json` รวมสถานที่ท่องเที่ยวราว 15 แห่ง พิกัดยืนยันจาก OpenStreetMap ใช้ร่วมกันทั้งการ์ดหน้าแรกและตัวเลือกต้นทางปลายทาง แต่ละการ์ดบอกจำนวนจุดเสี่ยงในรัศมี 2 กม. และระดับสูงสุด กดแล้วไปดูบนแผนที่หรือ "นำทางไปที่นี่"
- **C3 รายการโปรด** (S4) ปุ่ม ☆ ในหน้ารายละเอียด และส่วน "รายการโปรด" ในหน้าแรก
- **C4 ป้ายยืนยันแล้ว** (S6) "✓ ข้อมูลทางการ" แยกจาก "⚠️ ยังไม่ยืนยัน" ชัดเจน

### ช่วง D — ข้อมูลทางการและข้อมูลสด

- **D1 สคริปต์ดึงข้อมูลกระทรวงคมนาคม** ทำซ้ำได้ ปีหน้าทีมรันใหม่ได้ทันที ตัวแปลงวันที่ 4 รูปแบบและการจัดกลุ่มจุดเกิดเหตุมีเทสต์คุม ผลการวิเคราะห์บันทึกเป็นรายงานใน repo ให้อาจารย์ตรวจที่มาได้
- **D2 เพิ่มจุดเสี่ยงบนทางหลวงจากข้อมูลทางการ** ราว 5–8 จุด ที่อยู่ในสองอำเภอเป้าหมาย เกิดเหตุซ้ำอย่างน้อย 2 ปี และมีคะแนนถ่วงน้ำหนัก (ตาย 5 สาหัส 3 เล็กน้อย 1) ไม่ต่ำกว่า 10 จุดเหล่านี้ตั้ง `verified: true` ได้จริงตามนิยามของทีมเอง เพราะมาจากเอกสารทางการ
- **D3 สภาพคลื่นและฝนสด** (บทที่ 8) การ์ดในหน้ารายละเอียดของจุดจมน้ำและจุดน้ำตก และแถบเตือนในหน้าแรกเมื่อคลื่นสูง **แสดงผลอย่างเดียว ไม่เปลี่ยนสูตรคะแนน** เพื่อไม่ให้กระทบเทสต์ "ตรงกับม็อกอัพ" ออฟไลน์แล้วซ่อนการ์ดเฉย ๆ ไม่พัง
  - เกณฑ์คลื่นอิงช่วงของ **Douglas Sea Scale** (มาตรฐานสภาพทะเลที่ใช้สากล): ต่ำกว่า 0.5 ม. สงบ · 0.5–1.25 ม. คลื่นเล็กน้อย ระวังเด็ก · 1.25–2.5 ม. คลื่นแรง ไม่ควรลงเล่นน้ำ · เกิน 2.5 ม. อันตรายมาก ห้ามลงน้ำ
  - เกณฑ์ฝนอิงระดับความแรงฝนรายชั่วโมงของ **WMO**: ต่ำกว่า 2.5 มม./ชม. ฝนเล็กน้อย · 2.5–7.6 ฝนปานกลาง · เกิน 7.6 ฝนหนัก (สำหรับน้ำตก ฝนปานกลางขึ้นไปเตือนเรื่องหินลื่นและน้ำหลาก)
  - ทุกการ์ดมีข้อความกำกับว่า *"ข้อมูลพยากรณ์ ไม่ใช่ประกาศทางการ ให้ยึดธงเตือนและคำสั่งเจ้าหน้าที่เป็นหลัก"*

### ช่วง E — ปล่อยใช้งานจริง (ต้องขออนุญาตก่อนทุกขั้น)

- **E1** อัปโหลดขึ้น Snack (สิ่งที่รายวิชาต้องการ)
- **E2** ขึ้น GitHub ให้ทีมทำงานร่วมกัน (ตามบทที่ 6.1)
- **E3** เว็บจริงผ่าน GitHub Pages ได้ลิงก์ที่ใครก็เปิดได้

ทั้งสามข้อเป็นการเผยแพร่สู่สาธารณะ จะถามก่อนทำทุกครั้ง

## 4. สถาปัตยกรรม

คงโครงสร้าง 4 ชั้นเดิม (`utils/` → `hooks/` → `components/` → `screens/`) กฎเดิมยังใช้ทุกข้อ: `utils/` ห้าม import React และใส่นามสกุล `.js` ส่วนชั้นอื่นไม่ใส่

### 4.1 หน่วยใหม่ในชั้น `utils/` (คณิตศาสตร์ล้วน เขียนเทสต์ก่อนทุกตัว)

| ไฟล์ | หน้าที่ | ฟังก์ชันหลัก |
|---|---|---|
| `utils/search.js` | ค้นหาและเรียงความเกี่ยวข้อง | `searchPoints(points, query)` เรียง: ชื่อขึ้นต้นด้วยคำค้น > ชื่อมีคำค้น > ประเภทอันตราย > อำเภอ |
| `utils/routeProgress.js` | ผู้ใช้อยู่ตรงไหนของเส้นทาง | `locateOnRoute(route, position)` → `{ alongM, offRouteM }` และ `nextRiskOnRoute(pointsOnRoute, alongM)` |
| `utils/simulation.js` | ตำแหน่งเสมือนเมื่อวิ่งไปได้ระยะหนึ่ง | `positionAtDistance(route, distanceM)` |
| `utils/alertMessage.js` | ประโยคที่พูดเตือน | `buildAlertMessage(point, distanceM, { alongRoute })` ปัดระยะให้พูดง่าย |
| `utils/season.js` | ข้อความแถบฤดูกาล | `summarizeSeason(points, month)` → `{ title, body, pointsInPeak }` |
| `utils/conditions.js` | จัดระดับคลื่นและฝน | `classifyWaves(heightM)`, `classifyRain(mm)` และ `fetchConditions(coordinate)` แบบมีหมดเวลาและไม่ throw เหมือน `routing.js` |

**ลดโค้ดซ้ำ:** `findRiskPointsAlongRoute` ใน `routeAnalysis.js` ใช้คณิตศาสตร์เดียวกับ `locateOnRoute` (ฉายจุดลงเส้นทางแล้วหาระยะสะสม) จะถูกปรับให้เรียกใช้ `locateOnRoute` แทนการเขียนซ้ำ เทสต์เดิม 15 ข้อต้องยังผ่าน

### 4.2 สถานะที่ใช้ร่วมกันทั้งแอป

ตอนนี้ทุกหน้าจอเรียก `useSavedPoints` แยกกัน ข้อมูลจึงไม่ซิงก์ข้ามแท็บ (F7) และรายการโปรดจะเจอปัญหาเดียวกัน

**วิธีแก้:** เพิ่ม `hooks/AppDataProvider.js` ครอบทั้งแอปใน `App.js` เก็บจุดที่บันทึกเองและรายการโปรดไว้ที่เดียว หน้าจอไหนแก้ ทุกหน้าจอเห็นทันที `useSavedPoints` และ `useFavorites` ตัวใหม่อ่านจาก Provider นี้ หน้าจอเดิมไม่ต้องแก้

### 4.3 โหมดเดินทางรับตำแหน่งได้สองแหล่ง

```
TripModeScreen
  ├── mode = 'gps'       → useUserLocation({ watch: true })     ตำแหน่งจริง
  └── mode = 'simulate'  → useSimulatedLocation({ route, speedKmh })  ตำแหน่งเสมือน
                               ↓ ทั้งสองแบบให้ { lat, lng } รูปแบบเดียวกัน
                         evaluateTripAlerts(...)   ← ตรรกะเดิม ไม่ต้องแก้
                               ↓ มีการเตือนใหม่
                         useVoiceAlerts().speak(buildAlertMessage(...))  + Vibration
```

ตรรกะการเตือน (`evaluateTripAlerts`) ไม่รู้และไม่สนว่าตำแหน่งมาจากไหน จึงไม่ต้องแก้และเทสต์เดิมยังใช้ได้

หน้าวางแผนเส้นทางส่งเส้นทางและจุดเสี่ยงบนเส้นทางไปให้โหมดเดินทางผ่าน navigation params

### 4.4 Dependency ใหม่

| แพ็กเกจ | ใช้ทำอะไร | ทำไมเลือกตัวนี้ |
|---|---|---|
| `expo-speech` | พูดเตือนภาษาไทย | เป็นโมดูลของ Expo เอง ใช้ได้ใน Expo Go และ Snack บนเว็บใช้ Web Speech API |

การสั่นใช้ `Vibration` ที่มากับ React Native อยู่แล้ว ไม่ต้องเพิ่มแพ็กเกจ (บนเว็บใช้ `navigator.vibrate` ได้บน Android ส่วน iOS บนเว็บไม่สั่น ซึ่งยอมรับได้เพราะมีเสียงแล้ว)

### 4.5 ไฟล์ข้อมูล

- `data/riskPoints.json` — แก้พิกัด เพิ่มจุดทางหลวงจากข้อมูลทางการ **ไม่เปลี่ยนโครงสร้างฟิลด์**
- `data/places.json` — ใหม่ `{ id, name, emoji, district, coordinate }`
- `data/presetRoutes.json` — แก้พิกัดต้นทางปลายทาง
- `data/SOURCES.md` — ใหม่ บันทึกที่มาของพิกัดทุกจุดและรายงานการวิเคราะห์ข้อมูลกระทรวงคมนาคม

## 5. การจัดการข้อผิดพลาด

| สถานการณ์ | พฤติกรรม |
|---|---|

## 7. สิ่งที่จะไม่ทำ

- **ไม่เปลี่ยนสูตรคะแนนหรือ `N_MAX`** สูตรถูกตรึงด้วยเทสต์ "ตรงกับม็อกอัพ" และเป็นการตัดสินใจเชิงนโยบายของทีม ข้อมูลสภาพอากาศสดจึงแสดงแยก ไม่คูณเข้าคะแนน
- **ไม่มีเซิร์ฟเวอร์ ไม่มีระบบสมาชิก** ตามขอบเขตในบทที่ 1.3 และ 6.2
- **ไม่ค้นหาที่อยู่ใด ๆ แบบอิสระขณะใช้แอป** (geocoding) นโยบายของ Nominatim ไม่อนุญาตให้แอปเรียกใช้หนัก และขัดกับเป้าหมายใช้งานออฟไลน์ได้ ใช้รายการสถานที่ที่คัดไว้แทน
- **ไม่ย้ายจุดเดิมของทีมไปวางบนจุดรวมเหตุทางการ** จุดเดิมแก้เฉพาะพิกัดให้ตรงกับชื่อสถานที่ จุดจากข้อมูลทางการเพิ่มเป็นจุดใหม่
- ไม่ทำ UI ภาษาอังกฤษ ไม่ทำโหมดมืด

## 8. ลำดับการทำ

```
A (แก้ของพัง) → B2 จำลอง → B1 เสียง → B3 ตำแหน่งบนเส้นทาง
   → C2 สถานที่ → C1 เลือกต้นทางปลายทาง → C3 โปรด → C4 ป้าย
   → D1 สคริปต์ → D2 จุดทางการ → D3 สภาพอากาศสด
   → ตรวจทั้งแอปรอบสุดท้าย → E (ถามก่อน)
```

ทำโหมดจำลอง (B2) ก่อนเสียง (B1) เพราะพอมีโหมดจำลองแล้ว ทุกฟีเจอร์ของโหมดเดินทางที่ตามมาทดสอบในเบราว์เซอร์ได้ทันทีโดยไม่ต้องปลอม GPS ด้วยมือ

ทุกช่วงจบด้วย: เทสต์ผ่านทั้งหมด → build เว็บสำเร็จ → ตรวจในเบราว์เซอร์จริง → commit

## 9. ความเสี่ยง

| ความเสี่ยง | การรับมือ |
|---|---|
| เสียงภาษาไทยบนเว็บขึ้นกับระบบปฏิบัติการของผู้ใช้ | ตรวจและแจ้งผู้ใช้ ภาพกับการสั่นยังทำงาน บนมือถือ Android/iOS มีเสียงไทยในตัว |

| ข้อมูลกระทรวงคมนาคมไม่รวมถนนเทศบาล | ระบุชัดใน `data/SOURCES.md` จุดในเมืองยังใช้ข่าวเป็นแหล่ง |
| Open-Meteo อาจไม่ส่ง CORS header ให้เบราว์เซอร์ | ตรวจเป็นอย่างแรกของช่วง D3 ถ้าไม่ได้ ตัดข้อนี้ออก |
| `expo-speech` บน Snack | เป็นโมดูลมาตรฐานของ Expo SDK 54 ตรวจอีกครั้งตอนช่วง E |
