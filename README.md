# AntacinnHelp

แอปพลิเคชันแผนที่เตือนจุดเสี่ยงสำหรับนักท่องเที่ยว พื้นที่อำเภอหาดใหญ่และอำเภอเมืองสงขลา

## ⚠️ อ่านก่อนใช้งาน: สถานะข้อมูล

**4 จาก 12 จุด** กรอกข้อมูลเหตุการณ์จริงที่มีแหล่งอ้างอิงแล้ว ได้แก่
ทางขึ้นเขาคอหงส์ · หาดชลาทัศน์ · น้ำตกโตนงาช้าง · สะพานติณสูลานนท์

**อีก 8 จุดยังว่าง** (`incidents: []`, `source: "⚠️ รอกรอกข้อมูลจริง"`) เพราะยังหาแหล่งอ้างอิงระดับจุดไม่ได้
เป็นแบบนี้โดยตั้งใจ ตามกฎที่ทีมเขียนไว้เองในเอกสารบทที่ 6.3:
**ห้ามบันทึกตัวเลขสถิติที่ปราศจากแหล่งอ้างอิง**

### ทำไมทุกจุดยังเป็น `verified: false`

เพราะ `UNVERIFIED_TEXT` ใน `constants/config.js` ที่ทีมนิยามไว้เองระบุว่า
*"ยังไม่ได้ยืนยันจากเอกสารทางการ อาจมาจากการสอบถามผู้อยู่ในพื้นที่**หรือรายงานข่าว**"*

ข้อมูลที่กรอกไปมาจาก**รายงานข่าว** จึงยังไม่เข้าเกณฑ์ `verified: true` ตามนิยามของทีมเอง
จะเปลี่ยนเป็น `true` ได้ต่อเมื่อมีเอกสารทางการ เช่น บันทึกของ สภ. ในพื้นที่
หรือสถิติจาก ศปถ.จังหวัด ที่ระบุถึงจุดนั้นโดยตรง

### ข้อจำกัดสำคัญของตัวเลขที่กรอกไว้

ตัวเลขมาจากข่าว **ข่าวรายงานเฉพาะเหตุที่รุนแรงหรือมีคนตาย** เหตุเล็กน้อยแทบไม่เป็นข่าว
ดังนั้น **จำนวนจริงย่อมสูงกว่าที่บันทึกไว้เสมอ** และคะแนนที่คำนวณได้คือ *ขั้นต่ำ* ไม่ใช่ค่าจริง
ห้ามตีความว่าจุดที่คะแนนต่ำแปลว่าปลอดภัย

### ข้อมูลทางการที่มี — แต่ใช้รายจุดไม่ได้

ชุดข้อมูล **"สถิติอุบัติเหตุทางถนนในพื้นที่จังหวัดสงขลา"** ของสำนักงานจังหวัดสงขลา
(data.go.th ชุด `dpm08` สัญญาอนุญาต Open Data Common ที่มา: ระบบ e-report)
รายงานช่วง 1 ม.ค. – 13 มิ.ย. 2568 ไว้ว่า

| อำเภอ | อุบัติเหตุ | บาดเจ็บ | เสียชีวิต |
|---|---|---|---|
| หาดใหญ่ | 11 ครั้ง | 3 คน | 9 คน |
| เมืองสงขลา | 20 ครั้ง | 16 คน | 5 คน |

ข้อมูลชุดนี้เป็น **ระดับอำเภอ** ไม่ใช่ระดับจุด จึงเอามาใส่ `incidents` ของจุดใดจุดหนึ่งไม่ได้
การเกลี่ยตัวเลขอำเภอลงไปตามจุดต่าง ๆ ก็เท่ากับแต่งข้อมูลขึ้นเอง จึงไม่ทำ
ใช้เป็นบริบทภาพรวมได้เท่านั้น

### วิธีกรอกข้อมูลเพิ่ม

เติม `incidents`, `peakMonths`, `peakHours`, `advice`, `source` ในไฟล์ `data/riskPoints.json`
คะแนนกับสีหมุดจะเปลี่ยนตามเอง **ไม่ต้องแก้โค้ดสักบรรทัด**

- ใส่ `peakMonths` / `peakHours` **เฉพาะเมื่อมีหลักฐานรองรับ** เพราะสองค่านี้เป็นตัวคูณคะแนน
  (ฤดูกาล 1.3 เท่า เวลา 1.1 เท่า) ใส่มั่วจะดันคะแนนให้สูงเกินจริง
- ทุกรายการใน `incidents` ควรมี `note` บอกว่าเหตุการณ์นั้นคืออะไรและเกิดวันไหน
- `source` ต้องระบุชื่อสำนักข่าวหรือหน่วยงาน พร้อมวันที่ ให้คนอื่นตามไปตรวจสอบได้

## วิธีรัน

### บนมือถือ (แนะนำ — แผนที่สมบูรณ์ที่สุด)
1. ติดตั้งแอป **Expo Go** จาก Play Store / App Store
2. เปิด Snack ของโปรเจค แล้วสแกน QR code

### บนเว็บผ่าน Snack
กดแท็บ **Web** ใน Snack ได้เลย — แผนที่จะใช้ Leaflet แทน react-native-maps โดยอัตโนมัติ

### รันบนเครื่องตัวเอง
```bash
npm install
npx expo start
```
กด `w` เพื่อเปิดบนเว็บ หรือสแกน QR code ด้วย Expo Go

### รันเทสต์คณิตศาสตร์ (ไม่ต้องใช้ Snack ไม่ต้องต่อเน็ต)
```bash
npm test
```
ต้องได้ `pass 64` `fail 0`

## โครงสร้าง

| โฟลเดอร์ | หน้าที่ | ทดสอบ |
|---|---|---|
| `utils/` | คณิตศาสตร์ล้วน **ห้าม import react เด็ดขาด** | 64 เทสต์ |
| `hooks/` | GPS, การเก็บข้อมูลลงเครื่อง, state | ทดสอบตอนรันแอป |
| `components/` | UI ที่ใช้ซ้ำหลายหน้า | ทดสอบตอนรันแอป |
| `screens/` | 6 หน้าจอของแอป | ทดสอบตอนรันแอป |
| `navigation/` | ผูกหน้าจอเข้าด้วยกัน | ทดสอบตอนรันแอป |

### กติกาที่ต้องรู้ก่อนแก้โค้ด

**1. นามสกุล `.js` ในบรรทัด import ไม่เหมือนกันแต่ละโฟลเดอร์ — ตั้งใจให้เป็นแบบนั้น**
- `utils/` กับ `tests/` **ต้องใส่** `.js` เพราะ Node รันตรง ๆ และ Node ไม่เติมนามสกุลให้
- `hooks/`, `components/`, `screens/`, `navigation/` **ห้ามใส่** เพราะ Metro เติมให้เอง

**2. แผนที่มีสองไฟล์ ห้ามแก้ไฟล์เดียว**
`AppMap.native.js` (มือถือ) กับ `AppMap.web.js` (เว็บ) ต้องรับ props ชุดเดียวกันเสมอ
Metro เลือกไฟล์ให้อัตโนมัติ หน้าจอเขียนแค่ `import AppMap from '../components/AppMap'`
`react-native-maps` ใช้บนเว็บไม่ได้ จึงต้องอยู่ใน `.native.js` เท่านั้น

**3. ห้ามมีสีเขียวใน `RISK_LEVELS`**
การไม่มีหมุดแปลว่า "ยังไม่มีข้อมูล" ไม่ได้แปลว่า "ปลอดภัย" — มีเทสต์คุมไว้แล้ว

**4. ค่าคงที่ในการคิดคะแนนห้ามแก้มั่ว**
`N_MAX=30`, `SEASON_PEAK=1.3`, `TIME_PEAK=1.1` ถอดมาจากม็อกอัพของทีม
มีเทสต์ชื่อ "ตรงกับม็อกอัพ" คุมไว้ว่าเขาคอหงส์ต้องได้ 43 พอดี ถ้าแก้แล้วเทสต์จะแดง
